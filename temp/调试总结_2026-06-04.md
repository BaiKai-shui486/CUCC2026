## 三个隐蔽 Bug

### Bug 1：损失归一化方式错误（影响最大）

```python
# ❌ 错误（导致梯度缩小 ~150x）：
total_weight = (lambda_weights * pair_mask).sum().clamp(min=1)
loss = weighted_loss.sum() / total_weight

# ✅ 正确（0.65 版本）：
num_pairs = pair_mask.sum().clamp(min=1)
loss = weighted_loss.sum() / num_pairs
```

**原理**：`total_weight = sum(|rank_i - rank_j|)` 对于 300 只股票约等于 670 万，而 `num_pairs` 约等于 4.5 万。用 total_weight 归一化相当于把学习率除以 ~150，梯度回到 1e-5 级别，模型学不动。

### Bug 2：nan_to_num(..., posinf=1e6) 注入极端值

评估循环中**无条件**执行 `torch.nan_to_num(sequences, posinf=1e6)`，将正常数据中的 inf 替换为 1e6，污染 StandardScaler 和模型输入。

### Bug 3：pair_mask 条件改变导致梯度方向丢失

```python
# ❌ 错误：
pair_mask = (true_diff > 0).float()  # 只保留一个方向

# ✅ 正确：
pair_mask = (true_diff != 0).float()  # 保留两个方向
sign = torch.sign(true_diff)           # 用 sign 处理方向
logistic_loss = torch.log(1.0 + torch.exp(-sigma * sign * pred_diff))
```

只保留 `true_diff > 0` 的配对会丢失 `sign` 信息，使 loss 无法区分正负方向。

## 经验教训

1. **一次只改一个变量**。改动叠加后无法定位问题
2. **输入数据中永远不要用 nan_to_num 的 posinf/neginf**。1e6 是极端值，会污染整个数据流
3. **归一化分母要仔细验证**。num_pairs vs total_weight 差 150 倍，直接决定模型能不能学
4. **保留已验证有效版本的完整代码快照**。每次改动前备份，方便回退
